# AI会议纪要

## 一、定位与产物

把会议材料压缩成高质量决策信息，而不是重排摘要或复述逐字稿。默认只回答五个问题：

1. 会议真正要解决什么？
2. 实际形成了什么决定？
3. 决定依赖哪些关键事实和假设？
4. 最大的遗漏、分歧或风险是什么？
5. 下一步最值得做什么？

把原始材料视为证据，把本 Skill 视为独立参谋。只保留影响决策、风险、资源或行动的内容。

先判断产物：

- **默认**：只生成“AI 会议纪要”。
- **用户明确要求复盘迭代，且存在历史基线**：在纪要中增加“迭代与下一轮”。
- **用户明确要求规划、决策推进或下一次会议设计**：另行生成“决策推进稿”。

会议类型本身不构成自动扩写理由。派生方案不是会议事实，必须与纪要分区或分文档呈现。

## 二、证据来源与缺失处理

材料可以来自飞书会议工具链、用户粘贴的文字或上传文件。飞书能力未安装、无权限或读取失败时，继续使用已有材料，不中止。

用户附有会议链接、逐字稿或文件时，直接以其为当前材料；用户说“昨天的会”时，定位最符合上下文的已结束会议，只有多个候选无法判断时才询问一次会议名称。

不同材料承担不同证据作用：

1. **逐字稿或妙记记录**：确认讨论过程、明确发言和决策状态。
2. **正式文件、数据和方案**：核验事实、数字、约束与决策条件。
3. **飞书智能纪要、章节和待办**：定位线索和交叉核验，不单独作为最终结论。
4. **项目背景和历史决策**：判断目标偏移、重复争论和前后冲突。

不要设置笼统的证据高低顺序：逐字稿证明“会上说了什么”，正式文件证明“事实和约束是什么”。口头说法不能自动覆盖正式文件；正式文件也不能证明会议已经形成决定。

按以下规则处理缺失与冲突：

- 始终记录材料来源、可读性和关键缺口。
- 缺少逐字稿或其他可核验的会议记录时，标记为“初步版”，并说明无法核验的内容及其对结论的影响。
- 材料冲突时不代为裁决；列出冲突内容、证据位置和待确认人。
- 负责人、时间或关键数字缺失时标记“待确认”，不代为编造。

使用飞书材料时，按需调用已安装的 `lark-vc`、`lark-note`、`lark-minutes`、`lark-doc` 或 `lark-drive` Skill，并先遵守对应 `SKILL.md`。

## 三、分析流程

### Step 1：找到真正的问题

判断会议属于信息同步、问题诊断、方案评审、正式决策、执行复盘、战略研讨或创意讨论。用一句话重写核心问题，不把会议标题直接当作问题。

### Step 2：重建讨论与决策

按议题抽取关键主张、证据、隐含假设、反对意见、替代方案和决定，不按时间写流水账。

决策状态只使用四种：

- **已确认**：授权人明确拍板或确认，执行方向已经成立。
- **暂定**：同意先试行或推进，但附有验证条件、复审点或回退安排。
- **倾向**：存在明显偏好，但授权人尚未确认或执行条件不完整。
- **未决**：关键选项仍开放，或因信息、权限、资源不足而没有形成决定。

沉默、模糊附和和无人反对不能单独构成“已确认”。

决策状态只用于选择、授权或行动承诺，不用于普通事实和风险陈述；非决策信息使用“已核验、待验证、存在冲突”等事实状态。

一个信息点至少满足一项才进入正文：改变决策条件；改变优先级、资源、负责人或时间；暴露关键假设、实质分歧或重大风险；解释根因；直接产生行动。

### Step 3：核验关键资料并选择最少的方法

只核验会改变结论的材料：关键数字是否一致或过期，文件限制是否被遗漏，目标、预算、排期和资源是否匹配，以及是否引用了未提供的材料。

普通同步会不加载重型框架。决策、诊断、复盘或高风险会议才读取 [references/methodology.md](references/methodology.md)，选择最少且真正有帮助的方法；方法名称不写进最终纪要。

### Step 4：形成诊断与行动

每项诊断包含“判断—证据—影响”，最多保留 1–3 项。优先识别目标偏移、关键假设未验证、伪共识、选项比较不足、责任悬空、资源不匹配和高影响风险；不要无证据推断参会人的动机或人格。

建议按 `P0 / P1 / P2` 排序，最多 5 项。尽量写明动作、负责人、时间、交付物或验收标准。

区分会议已经形成的行动与 Agent 新增建议；新增行动必须标记 `【AI建议】`，不能让读者误认为已经获得授权。

重要决定始终保留验证或验收条件；只有用户明确要求复盘或规划时，才扩展为独立的迭代章节、领先指标、复盘时间和退出条件。

### Step 5：按明确要求延伸

- **复盘迭代**：仅在用户明确要求且存在历史基线时，对照上轮承诺、目标和假设，标记“保留、修正、推翻、仍需验证”。没有历史基线时只建立本轮基线。
- **决策推进**：仅在用户明确要求时读取 [assets/decision-advance-template.md](assets/decision-advance-template.md)，把未决问题转成可供授权人选择的决策设计。新增内容标注 `【AI建议】` 或 `【待决策】`，不能写成会议共识。

## 四、唯一输出规则

以 [assets/ai-meeting-minutes-template.md](assets/ai-meeting-minutes-template.md) 为唯一结构来源，并按材料裁剪：

- 始终保留“30 秒结论”和“材料与完整度”。
- “关键结论与依据”同时承载决定性讨论、决策状态、事实状态、分歧和证据，不另建重复章节。
- 证据不足时不写空泛诊断，改列最关键的待验证问题。
- 没有明确行动或可靠建议时删除行动表，不为完整而编造。
- 用户未明确要求复盘迭代时，删除“迭代与下一轮”。
- 删除所有空章节和占位符；单项内容用短句，多项内容才用表格。

仅在边界可能混淆时使用：

- `【事实】`：被逐字稿、会议决定或文件直接支持。
- `【推断】`：Agent 根据证据形成的判断。
- `【建议】`：Agent 提出的行动或方案。
- `【待验证】`：材料不足或存在冲突。

执行压缩：

- 不设最低字数，能短则短；正文默认不超过 1200 个汉字，证据附件不计入。
- 最多保留 3–5 个关键因素、1–3 项诊断和 5 条建议。
- 结论先行，同一信息只出现一次。
- 删除会议常识、重复背景、无行动价值的过程，以及“加强沟通”“持续关注”等无动作和验收标准的空话。
- 若删去一段不会改变判断、风险或行动，就删掉。
- 用户明确要求深入分析，或会议涉及不可逆决策、重大成本、安全、法律、财务或高声誉风险时，可以扩展；详细论证仍放入附件。

微型质量示例：

- **不合格**：团队需要加强沟通，持续关注项目风险。
- **合格**：`【推断】` 上线日期依赖“接口联调一次通过”，但逐字稿 36:20 显示联调环境尚未开放，原排期至少缺少两天缓冲。`【建议】` 接口负责人周三 18:00 前交付可用环境，以首轮回归通过率验收。

## 五、质量与交付

交付前只检查五件事：

1. 是否一句话说清核心问题、决定和未决事项？
2. 关键判断是否有证据，并披露材料缺口或冲突？
3. 决策状态是否准确，重要异议是否被保留？
4. 诊断是否说明具体影响，行动是否可执行或验证？
5. AI 建议是否与会议事实分开，用户能否一分钟内知道下一步？

如果输出适用于任何会议，说明它过于泛化；回到原始材料重写。

用户提到“云文档”“飞书文档”“纪要文档”或要求可分享链接时，调用 `lark-doc` 创建飞书云文档：

- 优先使用用户或当前 Agent 配置的默认文档目录；没有配置时，保存到“AI 工作文档”或确认目标目录。
- 飞书写入不可用时，先在对话中交付完整纪要并说明未生成云文档。
- 创建成功后返回可复制的 `https://` 文档链接，并保留原始会议产物链接。

Skill 说明、方法论和安装资料保存到用户配置的 Skill 库，不与会议结果混放。用户继续追问时，沿用同一证据集讨论，不重复生成纪要。
