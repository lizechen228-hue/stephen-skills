# AI 会议分析方法论

## 原则

方法论是内部思考工具，不是输出目录。每次只选择能提高当前会议判断质量的最少组合；普通同步会无需套用重型决策框架。

## 一、科学边界：五种内容不能混写

1. **原始证据**：逐字稿、正式文件、数据和明确发言。
2. **会议结论**：授权人在会议中确认的决定。
3. **Agent 推断**：根据证据形成的解释和诊断。
4. **Agent 建议**：会议之外新增的方案、议程或负责人建议。
5. **执行结果**：会后真实发生的进展和经营结果。

从纪要生成下一次会议议程或决策设计很有价值，但它属于派生产物。将新增方案直接写入会议结论，会制造“伪共识”；只记录原话而不推动下一步，则无法形成经营闭环。

## 二、借鉴《贝佐斯如何开会》/ Working Backwards

### 1. 书面叙事，而不是要点堆砌

亚马逊用叙事文档代替幻灯片，以迫使作者写清事实、逻辑和因果关系。应用到会后纪要：先重建“问题—证据—选项—取舍—决定”，再压缩成要点；不要把逐字稿切碎后重新排列。

适用：方案评审、决策会、复杂问题讨论。

### 2. Working Backwards

从最终服务对象和理想结果向后检查当前决定：

1. 谁会因这个决定受益或受损？
2. 要改变的具体结果是什么？
3. 当前方案能否产生该结果？
4. 还缺少什么能力、条件或验证？

适用：产品、项目、客户、组织方案。内部事务也可把“客户”替换成最终使用者或承接者。

### 3. 单向门与双向门

判断决定是否易于撤回：

- 双向门：可低成本回退，建议小步试验、快速决策。
- 单向门：难以撤回或代价很高，要求更强证据、替代方案和风险控制。

不要让可逆决定被过度分析，也不要让不可逆决定在信息不足时仓促通过。

### 4. 保留异议，再承诺执行

检查会议中的不同意见是否被真实记录，还是被模糊成“已达成一致”。决定形成后，明确谁仍保留意见、团队是否承诺执行、什么新证据会触发重新评估。

适用：争议决策、跨团队协作、负责人意见不同的会议。

### 5. 可控输入指标

不要只写滞后结果，如收入、完成率或最终上线。寻找团队可以直接改变、且能领先反映结果的输入指标，并把它放进行动清单。

适用：经营复盘、项目进度、运营与增长会议。

### 6. 六页文档和静默阅读的边界

六页叙事和会前静默阅读主要改善会议输入质量，不应机械复制成六页会后纪要。若本次会议反复解释背景、参会人理解不一，可建议下一次会前提供短叙事材料并留出阅读时间；最终 AI 纪要仍应精炼。

## 三、补充的分析工具

### 1. 论证图：主张—证据—假设—反例

对关键判断检查四项：

- 主张：会议认为应该做什么或事实是什么？
- 证据：什么数据、经验或文件支持它？
- 假设：证据到结论之间依赖什么没有说出的前提？
- 反例：什么情况会让结论不成立？

只分析决定性主张，最多 3 个。

### 2. 决策质量检查

对正式决策检查：目标是否清楚、选项是否充分、证据是否可靠、关键取舍是否明示、不确定性是否承认、决定是否可逆、负责人是否明确。

如果没有比较替代方案，不要直接说决定错误；指出“尚未证明当前方案优于其他方案”。

### 3. 轻量 Pre-mortem

假设三个月后方案已经失败，找出最可能的 1–3 个原因。每个原因转成：早期信号、预防动作、应急动作。只用于有明确计划或重大执行风险的会议。

### 4. 行动闭环

行动项至少满足四项：单一负责人、完成时间、可见交付物、验收标准。依赖外部团队时补充前置条件。避免多人共同负责却无人最终负责。

### 5. 假设迭代

连续性会议不要重复总结背景。先对照上轮决策、行动和指标，再把关键假设标记为：

- 保留：仍被事实支持；
- 修正：方向保留，但路径、资源、目标或条件变化；
- 推翻：已被反证，应停止或重新选择；
- 仍需验证：缺少决定性证据。

每项“仍需验证”必须转成验证动作。每项“推翻”必须检查相关资源和项目是否同步停止。

### 6. 决策推进

把复杂会议转成下一轮决策稿时，按以下顺序：

1. 决策问题：本轮必须由谁决定什么；
2. 共同事实：各方已接受、会改变选择的事实；
3. 关键假设：仍不确定但必须显性化的前提；
4. 可选路径：至少比较两个真实选项，包括“不做”；
5. 推荐与取舍：选择什么、放弃什么；
6. 资源变化：增加、减少和停止什么；
7. 验证机制：结果指标、领先指标、首次复盘和退出条件。

不要用“只能选三项”“固定由某人负责”等强约束制造决断感，除非会议已确认该约束，或明确标记为 Agent 的会议设计建议。

## 四、按会议类型选择

| 会议类型 | 默认方法 | 重点产出 |
|---|---|---|
| 信息同步 | 关键因素过滤、行动闭环 | 变化、阻塞、负责人 |
| 问题诊断 | 论证图、根因追问 | 根因、证据、验证动作 |
| 方案评审 | Working Backwards、决策质量 | 目标、选项、取舍 |
| 正式决策 | 单/双向门、异议与承诺 | 决定、条件、反对意见 |
| 项目/经营复盘 | 输入指标、假设迭代、轻量 Pre-mortem | 偏差、学习、纠偏、复盘点 |
| 战略研讨 | 决策推进、Working Backwards、红队挑战 | 战略选择、资源取舍、停止清单 |
| 创意讨论 | Working Backwards、选项比较 | 用户结果、候选方向 |

## 五、从会议到经营迭代

重要会议形成以下链路：

`会前决策备忘录 → 会中形成选择 → 会后证据化纪要 → 行动与领先指标 → 定点复盘 → 假设更新 → 下一轮决策`

其中：

- 纪要保护事实可信度；
- 决策稿提高选择质量；
- 行动与指标保证执行；
- 假设更新形成组织学习。

只在认知、规则或方法具有跨场景复用价值时沉淀为组织知识，不把每次会议的临时意见都升级成制度。
